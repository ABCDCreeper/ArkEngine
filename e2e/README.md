# 端到端测试

浏览器里跑真实流程：学生推进任务、教师逐条核对验收标准、批注转任务并回执、过程评价与预警回应、
离线打卡补交、错题复习、管理端审计与学校归属、白板持久化与账号隔离、令牌失效处理。

## 本地运行

后端在构建产物存在时会一并提供前端页面，所以一个进程就能跑：

```powershell
# 1) 构建前端并启动（单进程单端口）
./start.ps1 -Prod -Demo

# 2) 另开一个终端运行
cd ArkEngine-main
node e2e/flows.cjs
```

也可以对着开发服务器跑（前端 5173 + 后端 5000）：

```powershell
./start.ps1 -Demo
$env:INNOARK_URL = 'http://127.0.0.1:5173'
node e2e/flows.cjs
```

## 环境变量

| 变量 | 说明 |
| --- | --- |
| `INNOARK_URL` | 被测地址，默认 `http://127.0.0.1:5000` |
| `PLAYWRIGHT_PATH` | 指定 playwright 模块路径；不设时按 `playwright` → `playwright-core` 依次解析 |
| `PLAYWRIGHT_CHANNEL` | 浏览器通道；本地默认 `chrome`，CI 下用装好的 chromium |
| `INNOARK_SHOTS` | 截图输出目录，默认 `.runtime` |

## CI 与两个仓库的推送顺序

`e2e` 工作流在后端仓库里，但会检出**前端仓库的 `main`** 来构建页面。因此：

- **先推前端，再推后端。** 反过来的话，后端推送触发工作流时前端 `main` 还是旧的，
  会把新后端和旧前端配在一起跑——历史上就出现过一次：前端比后端晚推 36 秒，
  端到端在第一个检查处失败，报错信息却完全看不出原因。
- 现在工作流里有一步 **Check frontend matches backend contract**：构建产物缺少新界面时
  直接报错并说明"请先推送前端"，不会再让端到端跑到一半给出费解的断言失败。
- 需要固定某个前端分支或标签时，用仓库变量 `FRONTEND_REF`（默认 `main`）；
  前端仓库名可用 `FRONTEND_REPO` 覆盖。
- 失败时工作流会保存 `server.log` 与 `e2e-failure.png`（失败现场整页截图）作为制品。

端到端自身也会在失败时打印地址、页面文本摘要、第一个任务卡的 HTML，并在页面完全没有新界面文案时
提示"前端构建产物可能落后于后端契约"，便于区分是后端没给数据还是前端没渲染。

## 说明

- 脚本会自行创建项目、批注与任务，不依赖固定数据；但**会修改数据**，建议对着
  `-Demo`（`.runtime/demo.db`）这类可重置的库运行。管理端还提供「重置演示数据」，可随时还原。
- CI 见 `.github/workflows/e2e.yml`：检出本仓库与前端仓库、构建前端、单进程启动后端后运行本套件。
